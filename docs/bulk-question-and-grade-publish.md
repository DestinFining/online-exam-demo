# 批量题库操作、匿名阅卷与一键发布成绩

## 题库批量操作

- `POST /api/v1/questions/batch`：接收 `{ "questions": [QuestionRequest, ...] }`，每次最多 200 道题。该接口使用事务；任何一题校验失败，整批回滚。
- `POST /api/v1/questions/batch-delete`：接收 `{ "ids": [1, 2, 3] }`，每次最多 500 道题。采用逻辑停用（`status=0`），不物理删除题目，以免历史答卷、刷题、收藏、笔记及试卷快照的外键失效。
- 单题删除同样改为逻辑停用。当前题库和新刷题/新组卷查询只选择启用题目。
- 前端批量添加支持粘贴 JSON 数组或导入 `.json` 文件。可先选择默认学科/知识点，逐题通过 `subjectId` 和 `knowledgePointId` 覆盖。

## 教师匿名阅卷

`GradeSummary` 不再返回 `userId`、`username` 或 `nickname`，仅返回稳定的匿名编号 `candidateLabel`（例如 `匿名考生-000123`），以及考试/成绩处理需要的字段。教师列表和详情都使用该编号。

## 一键发布本场全部成绩

- `POST /api/v1/grades/exam/{examId}/publish-all`
- 只处理该场考试状态为 `SUBMITTED`、`GRADED` 或 `PUBLISHED` 的答卷；尚在 `IN_PROGRESS` 的考生不参与本次发布。
- 对待阅卷答卷先尝试结算客观题和已完成的主观题；只要有任一答卷存在未评分的简答题/编程题，事务整体回滚，不会只发布其中一部分，并返回匿名编号及未完成原因。
- 已发布的答卷跳过并计入 `alreadyPublishedCount`；响应包含 `publishedCount` 和 `alreadyPublishedCount`。
- 教师仍只能操作自己创建的考试；管理员按现有 RBAC 授权。

## 手动回归测试

1. 教师批量导入包含单选题与简答题的 JSON，确认数量与题库列表一致。
2. 勾选当前页 2 道题，批量删除后确认它们从启用题库消失，历史试卷仍能查看快照。
3. 用教师登录，查看阅卷列表和答卷详情，确认不出现学生姓名/用户名，只出现匿名编号。
4. 先保留一份有未阅简答题的提交，点击一键发布，确认整体失败且没有部分发布。
5. 完成所有提交答卷的主观题评分，再点一键发布，确认返回发布数量；学生登录后能看到已发布分数。
